# Study Check

青チャートの学習を記録・管理するスマートフォン向け PWA。
勉強中にノートの隣にスマホを開いておく「伴走アプリ」として使う。

その日にやる問題は**ロジックで自動的に決まる**。AI も、アカウントも、通信も要らない。
開いたブラウザの中だけで完結する。

## 使い方

### GitHub Pages で開く

`main` に push すると、テストが通ったときだけ GitHub Pages へ自動で配られる
（`.github/workflows/pages.yml`）。

```
https://<GitHubの名前>.github.io/study-check/
```

**はじめに一度だけ**、GitHub の
リポジトリ → **Settings** → **Pages** → **Build and deployment** → **Source** を
**「GitHub Actions」** に切り替えること。これを切り替えないと、workflow は
デプロイのところで失敗する（テストとビルドまでは通る）。

切り替えたあと、Actions タブの `pages` を「Run workflow」で1回動かせば配られる。
以後は `main` へ push するたびに更新される。

スマホのブラウザでそのURLを開き、**ホーム画面に追加**すればアプリとして使える。
名前は「Study Check」、アイコンは青地に白いチェックが出る。一度開けばオフラインでも起動する。

アイコンは `icons/icon.svg` が元で、そこから PNG を作ってある。
地は縁まで塗ってあり、チェックは中心から一辺の80%の円の中に収めてある
（ホーム画面では端末ごとに違う形——丸・角丸・しずく——で切り抜かれるため、
透明な余白があると背景が抜け、端に寄せると欠ける）。
足りているかは `test/manifest.test.mjs` が見張っている。

```sh
# icons/icon.svg を直したら、PNG を作り直す
npm run build:icons
```

友達に使ってもらうときは、このURLを渡すだけでよい。学習データは**それぞれの端末の中だけ**に
入るので、同じURLを開いても他人の記録は見えないし、こちらからも見えない。

### 手元で動かす

ビルド不要。静的ファイルをそのまま配信すれば動く。

```sh
python3 -m http.server 8000
# → http://localhost:8000/ をスマホのブラウザで開き、ホーム画面に追加
```

初回起動時に `data/questions.json`（青チャート数学I+A の問題マスタ 593問）が投入される
（`src/seed.js`）。

はじめに設定するのは2つだけ。

1. **設定 → 目標** … 何を・いつまでに・どの状態まで
2. **設定 → 学習に使える時間** … 曜日ごとに1日何分使えるか

これだけで、アプリを開くたびに今日やる問題が並ぶ。

## はじめて開いたとき

使い方の案内が出る。別の説明画面は作らない。**本物の画面の上に穴を開けて指し、
実際にそこを押したときだけ次へ進む**。

```
まず「設定」を押す → 「目標」を開く → 目標を追加 → 名前と範囲を決めて作成 →
学習に使える時間 → 使える分を入れる → ホームへ戻る → 今日の分が並ぶ
```

**案内の文章は短くしてある。** 読み物ではなく、手を動かしてもらうためのもの。
くわしい説明（評価の意味・習得の条件・優先順位の働き方など）は
設定 → 使い方 に置き、必要になったときに読めるようにしてある。

案内が終わる前に予定を組むので、最後の「ここに今日やる問題が並ぶ」では本当に並んでいる。
それでも空になるときは、理由を添える。

いつでも「あとで」でやめられる。もう一度見たいときは 設定 → 使い方 から。

| ファイル | 役割 |
|---|---|
| `src/tour.js` | 案内の画面（穴・カード・進み方）。データは知らない |
| `src/tour-runner.js` | 「もう見たか」「その手順は終わったか」を実データで判断する |

指す先は `data-tour="..."` で本物の要素に付けてある。画面は操作のたび丸ごと
組み直されるので、穴の位置は毎フレーム測り直している。

## 自動スケジューリング

学習履歴・評価・目標の期限と優先順位・使える時間・問題ごとの所要時間から、
その日に取り組む内容をロジックで決める。

**同じ学習状態なら、いつ何度動かしても同じ予定になる。** AI の推論に頼らないので、
出力が揺れず、なぜその問題が出たかを説明できる。

決めていることの要点:

- **習得判定** … `perfect` 2回で「一応クリア」。弱点が付いたらクリアを解除する
- **復習周期** … `wrong_approach` は翌学習日、`calc_error` / `weak_writing` は
  3日 → 2日 → 翌学習日 と縮む、`better_solution` は軽く扱う
- **優先順位** … 弱点 → 未習得 → 安定した問題。復習は新規学習より必ず先
- **維持フェーズ** … 全部クリアしたら、代表的な問題だけを間を置いて復習する
- **新規の順番** … 教科書の掲載順を守る
- **目標 priority** … 新規進行だけを段階的に制御する。必要な復習は妨げない
- **時間配分** … 見積もりの確からしさに応じて、枠を 80〜95% まで使う
- **未完了** … 失敗とはみなさず、元の予定のまま繰り越す。理由は推測しない
- **期限** … 足りなければ知らせる。期限も範囲も習得条件も、勝手には緩めない
- **チャレンジ** … 頃合いを知らせるだけ。中身は利用者が決める

詳しい決まりごとは **[docs/scheduling.md](docs/scheduling.md)**。

設定 → 自動スケジュール から、押す前に「こうなります」を確認して当てられる。
入にしておけば、アプリを開いたときに自動で組み直す。

**変えないもの**: いま解いている問題・完了した予定・自分で入れた予定・過ぎた日の予定。
同じ案が二度当たることもない。

設定に置くのは操作だけにしてある（入／切と「今すぐ組み直す」）。予定の中身は
スケジュールタブとホームで見えるので、設定画面で繰り返さない。
例外は「お知らせ」で、予定を見ても分からないこと（期限に間に合わない・
チャレンジの頃合い）だけを、出るときに出す。

## データの置き場所

学習データはすべて**その端末のブラウザの中（IndexedDB）**にある。外へ送る仕組みは持たない。

保存先の名前は `study-check` で、このアプリ専用である。IndexedDB は「置き場所（パス）」ではなく
「配信元（オリジン）」ごとに分かれるので、同じ GitHub Pages に別のアプリ（study-todo など）を
置いていても、名前を分けておかないと中身まで共有され、覚えのない目標や予定が出てくる。

- サーバーもアカウントも無い。GitHub Pages は置き場所を貸しているだけで、記録は届かない
- 同じURLを開いても、記録は人ごと・端末ごとに分かれている
- 端末どうしの同期は無い。機種を変えるときは 設定 → バックアップ で JSON を書き出す
- ブラウザのデータを消すと学習記録も消える。大事なら先に書き出しておく

## 予定と実績の考え方

3つを区別している。

| ことば | 何か | 識別子 |
|---|---|---|
| 問題 | 例題50 のような、問題マスタ上の対象 | `question.id` |
| 予定項目 | 「その問題に今回取り組む」1件の予定 | `item.itemId` |
| 学習記録 | 「実際に今回取り組んだ」1件の結果 | `record.id` |

**1回の取り組み＝1件の学習記録**。同じ例題を2周目に解いても、同じ日に2回解いても、
記録は上書きされずに増える。逆に、やらなかった予定を別の日へ繰り越しても、
取り組み回数は増えない（学習記録には手を触れないため）。

学習記録の `planItemId` で「どの予定に対する取り組みだったか」を追える。

## スケジュールタブ

日付がずっと続く1本の並び。上へスクロールすれば過去、下へ行けば先の予定が出てくる
（端に近づくと自動で日を足す）。**タブを押すと、今日がちょうど画面の真ん中に来る**。

1日は「例題」と「エクササイズ」の2段で、中身は正方形のマスだけで表す。

- **過ぎた日** … その日に実際に取り組んだ記録（予定に無かったものも出す）
- **今日** … 今日の実績 ＋ まだ残っている予定（日付の下に「45/60分」のように時間も出る）
- **これからの日** … その日にやる予定

マスは1回の取り組み（またはその予定）で1つ。**文字は入れず色だけ**で、すき間なく並べる。
実績は塗りつぶし、未実施の予定は枠だけ。評価が入っていない実績は正解扱いにせず灰色にする。

色の意味は、右上の **ⓘ** と、設定タブのいちばん下の「ヘルプ（マスの見方）」で見られる。

日付を押すと、その日の詳細（実施した問題・チャレンジの中身・残っている予定・
繰り越しの履歴）へ移る。過ぎた日に残っている予定は、ここから理由をひとつ選んで
別の日へ繰り越せる。

## 目標と計画

目標は「何を・いつまでに・どの状態まで」を持つ。

- **何を** … 対象の問題ID一覧。設定画面で**章をいくつでも選び、単元でさらに絞れる**。
  選んだ時点の問題が対象として確定する（あとで問題マスタが変わっても対象は動かない）
- **いつまでに** … 期限（なしも可）と優先順位（priority 1〜5）
- **どの状態まで** … 「取り組む」（1回ずつ解けば達成。✕でも取り組みとして数える）か、
  「習得する」（その目標に結び付いた**最新**の取り組みが ◯完璧にできた であれば達成）

達成として数えるのは、その目標に結び付いた予定から実施された取り組みだけ。
2周目の目標を作っても、1周目の記録では達成にならない。

**学習に使える時間**は「**平日**」と「**休日**」の2つだけで決める。
片方だけ入れれば、もう片方にも同じ値を使う。勉強しない日は **0** と入れる。
未設定と0分は別物として扱い、未設定の日には時間があるとみなさない。

その日だけの例外（今日は0分にする・今日はあと○分・予備時間）は用意しない。
予定どおりに進まなかった日は、次に開いたときに組み直されるので、手で直す必要がない。

**所要時間の見積もり**は、本人の実績（同じ問題の近い条件 → 似た問題）→ 保存された仮見積もり →
種類と難易度の既定値、の順に決まる。初見と復習、通常とチャレンジは分けて扱い、
計測忘れ・中断・制限時間切れの記録は計算から外す（記録そのものは消さない）。
タイマーは「問題を始めてから評価を記録するまで」を測るので、答え合わせの時間は
はじめから含まれている（設定で切り替える項目は持たない）。

## ホーム画面

上半分＝タイマー（固定）、下半分＝可変エリア。学習中に画面遷移は行わない。

**タイマーは二段表示**。左上に小さく「学習時間」（セッション全体。問題を切り替えても止まらない）、
中央に大きく現在の問題の累積時間。

下半分は4状態を切り替わる。

1. **待機** — 今日の累計時間 ＋「学習を開始」。「やること / やったこと」の切り替え
2. **タスクリスト** — 例題を1問ずつ展開。チャレンジは1行として混在
3. **記録入力** — 5択を1タップで記録
4. **チャレンジ** — 制限時間付き。全体タイマーと問題ごとの累積ストップウォッチが並行して動く

記録した問題は**リストから消える**。記録後に次の問題が自動で始まることはなく、
**やりたい問題を自分でタップしたときに計測が始まる**（順番通りに進むことを強制しない）。

## チャレンジ

問題をタップして切り替えても**評価は聞かれない**。元の問題は一時停止するだけで、
戻れば続きから加算される。

問題リストの一番下にある「終了」を押すと、**そこで初めて全問の評価入力**に移る。

チャレンジの中身（どの問題を何問・どの難易度で）は自動では決めない。
章の例題が仕上がると「challenge ready」とだけ知らせるので、何を解くかは自分で選ぶ。

## 記録タブ

章 → 単元 → 例題とたどり、その例題の取り組み履歴を見る。取り組み1回につき正方形のマスを1つ、
古い順に並べる（同じ日の2回分もまとめない）。マスを押すと、その回の日時・評価・所要時間・
通常かチャレンジかが出る。

## タイマーの設計

経過時間は `setInterval` の加算ではなく、開始時刻（`Date.now()`）との差分から算出する。
バックグラウンド遷移・画面スリープ・アプリの再起動をまたいでも正しい経過時間を保つ。

セッション状態は `SessionState` として IndexedDB に永続化され、
アプリを閉じても計測中の状態が復元される。

## 評価の5択

| 値 | 記号 | ラベル |
|---|---|---|
| `perfect` | ◯ | 完璧にできた |
| `better_solution` | 解 | 正解だが、もっと簡単な解法があった |
| `weak_writing` | 記 | 正解だが、記述が甘い |
| `calc_error` | △ | 計算ミス |
| `wrong_approach` | ✕ | 方針が違った |

メモ欄・原因タグは設けない（原因は5択に内包される）。

## テスト

2層ある（どちらも Node 標準のテスト。本体は引き続きビルド不要）。

```sh
npm test          # 判定のしかた（習得判定・復習周期・自動スケジュール・安全な適用・記録・予定）
npm run test:e2e  # 実ブラウザでの通し確認（Playwright が要る）
npm run test:all  # 両方
```

`npm test` は速く、ブラウザを要らない。`npm run test:e2e` は本物のブラウザで、
**タップ → IndexedDB → Service Worker → 再起動 → オフライン → 自動スケジュール**までを
1本で通す。Playwright が入っていない環境では、E2E は落ちずに飛ばされる。

## 日付の扱い

「今日」は日本時間（UTC+9）で判断する（`src/datetime.js`）。ISO文字列の先頭10文字をそのまま
使うと、深夜〜朝に前日として扱われてしまうため、日付の判定はすべてこのモジュールを通す。
学習日は 03:00 JST を境に切り替わる（深夜まで勉強しても同じ日として数える）。

## 問題マスタ

`data/questions.json` は、数研出版「改訂版 チャート式基礎からの数学I+A（青チャート）」の
**管理用メタデータ**である。問題文と解答は含まない。

| | 数学I | 数学A | 計 |
|---|---|---|---|
| 例題（基本・重要・演習） | 194 | 158 | 352 |
| EXERCISES | 134 | 107 | 241 |
| 計 | 328 | 265 | 593 |

1問 = 「1回解いて1回評価する単位」。例題の (1)(2)(3) は同じ1問として扱う。

各例題は SELECT STUDY の3コース（基本定着170問 / 精選速習174問 / 実力錬成135問）を持つ。

問題マスタは `masterVersion`（単調増加の版）を持つ。中身を変えたら
`tools/build-questions.mjs` の `MASTER_VERSION` を1つ上げること。起動時、同梱のマスタのほうが
新しい版なら、端末のマスタを入れ替える。

| EXERCISES の番号・難易度・所属する節 | 誌面（`tools/source/exercises.json`） |

EXERCISES の難易度は誌面の小さな丸数字から読み取ったもので、抜き取り検証で
読み違いが見つかったため `needsReview: true` を付けてある。

元データを直したら、次を実行して `data/questions.json` を作り直す（整合性チェックつき）。

```sh
npm run build:questions
```
